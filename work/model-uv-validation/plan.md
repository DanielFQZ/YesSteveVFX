# 新建模型 UV 与导出校验

## 问题与目标

新建编辑工程沿用了无模型特效载体的 1×1 UV 尺寸。导入已有模型时，Blockbench 对逐面 UV 与方盒 UV 的处理不同，可能生成超界方盒 UV，导致游戏 reload 拒绝该包。

## 规格

- 前置条件：用户新建编辑工程或导出包含模型的特效包。
- 新建模型允许指定 1–16384 的整数 UV 宽高，默认 16×16；不改变无模型载体。
- 导出前检查模型声明的宽高及方盒 UV 边界，与运行时保护检查一致。
- 不变量：不按 PNG 像素尺寸推断模型 UV，不自动修改源模型坐标，不移除运行时保护。
- 异常行为：非法尺寸在创建目录前报错；UV 越界阻止生成运行时包，指出文件与骨骼。
- 副作用：仅合法创建/发布操作写入工程；现场资源修复须先备份并核对原模型。

## 验证

- Node 回归测试覆盖非法方盒 UV、负坐标、逻辑 UV 与 PNG 分辨率不同、新建自定义/默认尺寸、非法尺寸无目录副作用。
- 现场模型依据原 bbmodel 的 UV 尺寸修复，逐面 UV 对照原模型；源工程与客户端包均通过扫描、校验和构建。
- 通过 Blockbench MCP 热重载插件并确认新建窗口字段。游戏 reload 与视觉效果由用户实测。
