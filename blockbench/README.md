# YesSteveVFX Studio（Blockbench 插件）

桌面版 Blockbench 插件，用于管理一个特效包里的模型、动画、粒子与贴图，编辑源文件，并生成 YesSteveVFX 使用的运行时包。当前插件版本：**0.2.3**。无需修改 Blockbench、YSM 或 eyelib。

## 安装 / 更新

1. 在 Blockbench 的插件管理中加载 `blockbench/yesstevevfx_studio.js`，保持文件名不变。
2. 更新文件后，在插件管理中重载插件。请先保存已经打开的编辑内容；重载后重新使用 VFX 导入目录，建立编辑会话。
3. 允许插件访问本地文件。顶部会出现 **VFX** 菜单。这套目录管理流程不支持网页版 Blockbench。

## 打开包并选择模型

1. 点击 **VFX → 导入工程文件夹**，选择包含 geo、animation、粒子 JSON 和 PNG 的源目录，也可以选择客户端中的已有特效包。
2. 插件提示扫描数量，并显示 **模型选择窗口**。每个条目列出模型路径、geometry identifier、geometry 下标、骨骼/方块数量、关联特效、动画文件、文件中的动画数量和动画名称。
3. 已有合法运行时包会根据 effect 和 client entity 恢复关联。只有原始文件、且存在多个候选模型时，插件不会自动猜测模型。点击该模型的 **关联动画与贴图**，勾选属于它的动画并选择模型贴图。
4. 点击 **打开 / 切换标签**，打开选中的源 geo，并导入关联 animation.json 中的**全部动画**。即使只有部分动画绑定给这个模型，文件里的其它动画也会在列表显示；显示不代表自动绑定给当前模型。
5. 在动画模式自行选择动画，按空格播放。包中的粒子 JSON 会全部载入预览库。
6. 使用 **VFX → 切换模型 / 打开其他模型** 打开另一个模型。相同模型复用原标签；不同 geo，以及同一 geo 内不同的 geometry，各自使用独立标签。

一个特效仍对应一个模型实例；一个包可以有多个模型。若同一动画要用于多个模型，分别关联即可，插件会生成名称不重复的独立特效。

导出时，同一个源 `geo` / `geometry` 被多个特效使用只会写入一份运行时模型文件和一份 animation JSON，多个 client entity 共享 geometry identifier，并从这份 animation JSON 中引用各自的动画 ID。这样重新导入客户端包时不会把同一个模型或动画误显示成多个文件；不同源模型仍会分别列出。

## 粒子绑定与别名

打开 **VFX → 资产与绑定**，左侧选择特效。右侧按 **时间 + 同一帧内事件序号 + 原别名 + 定位器** 列出每个粒子事件，分别选择对应的粒子 JSON。在“粒子与贴图”页为粒子选择 PNG；模型贴图独立配置。

每个特效详情顶部还会显示对应的 YSM 指令帧 Molang，例如 `ctrl.vfx_play('demo_pack:slash', 'main');`。点击 **复制** 后可直接粘贴到 YSM 动画的“动画效果 → 指令”帧；特效名或包 ID 修改后，显示内容会同步更新。

例如两个事件都叫 `12`，现在可以将事件 1 绑定到 `particles/12.json`，事件 2 绑定到 `particles/中文/12.json`。源粒子的 identifier 即使相同，也不会在导出时合并成一个资源。无法唯一判断的关系需要手动选择，插件不会用模糊匹配强行填充。

在 Blockbench 原生粒子帧中选择文件后，保存时插件会根据该帧的实际文件路径确认粒子身份：

- 普通、无歧义的用户别名会保留。
- 同一别名指向不同文件，或别名为内部预览 ID 时，改为稳定的 `vfx_<hash>` 别名。
- 粒子文件最终需要位于源工程目录。可以直接在 Blockbench 选择外部文件，然后使用 **同步外部资产到特效包**，无需手动搬运。
- 导出时在动画副本中生成稳定别名，同时写入完全一致的 client entity 映射。导出本身不修改源动画。

Blockbench 原生下拉框可能仍显示粒子 identifier 或文件名；插件保证保存与导出绑定正确，不修改 Blockbench 原生下拉框的实现。若多个候选名称相同，用 VFX 的逐事件面板按完整相对路径选择资源。

动画里的粒子事件本身只记录别名与定位器。运行时的资源关联链是：

```text
manifest.json → effects/*.json → client entity
                              ├─ geometry → geo 模型
                              ├─ animations → animation 动画
                              ├─ particle_effects → 粒子 identifier
                              └─ textures / render_controllers → 贴图与渲染配置
```

`vfx-project.json` 保存编辑器关系，不是游戏运行时依赖。已有版本 1 的别名绑定会迁移到逐事件绑定；迁移不能恢复本来就错误的旧绑定，仍需人工核对。

## 保存和共享动画

- **文件 → 保存模型**直接写回源 geo，并保留同文件内其它 geometry。Ctrl+S 如果绑定为“保存项目”，保存的是 bbmodel，请使用明确的“保存模型”菜单。
- **动画行 / 动画文件分组的保存按钮**写回真实 animation.json。VFX 管理的标签会经过粒子校正、冲突检查和备份，其他普通 Blockbench 工程不受影响。
- **VFX → 保存当前编辑回工程**保存当前标签的模型、动画和已修改的模型贴图，同时保存工程绑定。
- **资产与绑定 → 保存工程绑定**保存配置，并根据已保存的源文件更新当前包的运行时资源；它不保存尚未写回的模型、动画或贴图。
- 资产与绑定面板中的 **删除当前特效** 只删除特效注册和绑定，不删除 geo、动画、粒子或贴图源文件；保存后运行时 manifest 会同步移除该特效。

独立工程的编辑备份位于源目录同级的 `<工程名>-edit-backups/<时间戳-随机后缀>/`。直接编辑 `packs/<包名>` 时，备份放在 `packs` 外的 `yesstevevfx/vfx-edit-backups/<包名>/`，避免被游戏当成特效包扫描。原生“保存模型”仍使用 Blockbench 自身的保存机制，不生成 VFX 编辑备份。

同一 animation.json 可以在多个模型标签内预览和编辑。保存时会检查**该动画条目**是否自打开以来被其他标签或外部程序修改。如果发生冲突，阻止覆盖，保留当前标签的未保存内容。请先将当前改动另存为 bbmodel 备份，关闭过时的标签，再从模型选择窗口打开最新版本。不同动画条目的保存会合并，保留文件中其它动画。

编辑结束后先保存，再导出。导出使用磁盘上的源资源；如果标签中还有未保存的动画、模型或贴图修改，插件会阻止导出并提示先使用“保存当前编辑回工程”。

## 新建与添加资产

**VFX → 新建特效包**：选择父目录，填写包 ID、显示名称、初始模型文件名和初始动画文件名。插件会自动创建一个可打开的空模型和空动画，并把文件名规范为 `<填写名>.geo.json` 与 `<填写名>.animation.json`；如果输入时已经带有这些后缀，不会重复追加。随后可以直接打开模型标签，在 Blockbench 中继续编辑。空包会预先建立一个模型动画预览绑定，保存后再执行 **VFX → 重新扫描资产** 或继续使用当前工程即可。

扫描到的新动画会自动加入特效列表。可以修改对外特效名、持续时间和启用状态；取消左侧复选框即可不导出。取消某个模型的动画关联会将对应特效停用，重新关联后可以继续配置。无需手写每个动画的运行时 effect JSON，导出器自动生成。

源目录、文件名和显示名可以使用中文。包 ID 和游戏内特效 ID 仍遵循 Minecraft 规则，使用小写 ASCII 字母、数字、点、横线或下划线；导出的资源路径也会自动转为合法 ASCII 路径。

## 同步外部资产

在通过 VFX 打开的模型标签中，可以先使用 Blockbench 原生功能导入外部粒子、贴图或动画，再点击 **VFX → 同步外部资产到特效包**。资产与绑定窗口的工具栏也有同名按钮。

1. 扫描当前标签中粒子帧实际选中的 JSON、这些粒子的贴图、贴图列表中的外部或未保存图片，以及已导入的外部动画文件。其它模型标签不参与此次同步。
2. 优先使用 Blockbench 已选择的粒子预览贴图，其次按粒子 JSON 的路径寻找 PNG。找不到或路径有歧义时，弹出选择窗口，为每个缺失项指定 PNG。
3. 在同步预览中检查源文件和包内位置；如果模型有多个贴图，可选择该模型实际使用的贴图。当前运行时每个模型仍使用一张默认贴图。
4. 点击 **复制并更新引用**。外部资产写入 `assets/eyelib/particles/`、`assets/eyelib/textures/`、`assets/eyelib/animations/`，默认保留原文件名，例如 `assets/eyelib/particles/12.json`。同名且内容不同时才追加 `_2`、`_3` 等数字后缀；重复同步相同文件会复用已有文件。外部原文件不会移动或修改。
5. 粒子帧的文件路径和别名、模型贴图关系、外部动画的保存路径会更新到包内。新增资产立即进入 VFX 索引，不需要再次扫描。
6. 点击 **保存当前编辑回工程**，或使用动画保存按钮，将新引用写回动画 JSON。插件随后自动生成当前包的运行时资源和实体映射；若直接编辑客户端包，执行 `/vfx_client reload` 即可。绑定不完整时会明确提示“源文件已保存，运行时包尚未更新”。

外部贴图有未保存绘制修改、或图片尚未保存到磁盘时，同步会把当前画布结果保存为包内 PNG。分层编辑信息仍留在当前 Blockbench 标签中；PNG 只包含合成后的图像。

同步是一次显式归档，不会持续监视并覆盖包内副本。同步后编辑包内版本；外部原文件后续的变化不会自动传入。撤销/重做可恢复当前标签的引用与绑定，已复制文件保留在包内。外部动画中只有别名、未选择具体粒子文件的事件仍需手动绑定，不会按模糊名称猜测。子粒子事件仍遵循当前导出器的不支持限制。

## 导出到客户端

1. 在资产与绑定中点击 **检查引用**，修复未绑定的模型、粒子、贴图或不存在的定位器。
2. 点击 **导出到客户端**，选择 `.minecraft`；检测到 `versions` 时，选择实际使用的隔离版本。也可以直接选择隔离版本目录。
3. 新包写入 `config/yesstevevfx/packs/<包ID>`。已存在的目标包移到 `config/yesstevevfx/vfx-backups/`。
4. 游戏中执行：

```text
/vfx_client reload
/vfx_client play <包ID>:<特效名> test
```

**直接编辑客户端包时，无需导出到同一目录。** 动画保存按钮和“保存当前编辑回工程”会同时更新运行时包。只用原生“保存模型”、改了粒子 JSON 或从外部程序修改文件后，点击 **VFX → 更新当前包的运行时资源**，再执行 `/vfx_client reload`。独立源工程仍可使用“导出到客户端”；完整导出目标仍不允许与源目录重叠。

编辑资产（包括 `assets/eyelib/particles`、`assets/eyelib/textures` 和 `assets/eyelib/animations`）与游戏用资源分开保存。生成器把完整的运行时副本写到 `assets/eyelib/<资源类型>/vfx_generated/<包ID>/`，规范化粒子 identifier、贴图路径与动画事件别名，生成 client entity 和 effect 定义，并更新 manifest。Blockbench 继续关联源资产；请勿直接编辑 `vfx_generated` 中的生成文件。重新扫描时这些副本不会重复进入编辑资产列表。

不要将编辑备份或导出备份放进 `packs`。运行时 `/vfx_client reload` 会自动注册导出的特效。

## 预览与限制

Blockbench 预览使用其自己的粒子模拟器，游戏使用 eyelib；预览用于核对资源、时间点、定位器和动画，不代表二者渲染结果完全一致。先确认同一动画在 Blockbench 中是否完整，再比较游戏。

当前不导出声音事件、动画控制器和子粒子事件。配置检查会明确提示；不会为了导出而静默删除这些内容。

测试：在仓库根目录运行 `node --test blockbench/tests/studio.test.js`。
